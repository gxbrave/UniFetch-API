# iPhone 快捷指令配置

快捷指令使用后端返回的签名媒体地址。视频和静态图片可以直接使用系统的“存储到相簿”；`live_photo` 媒体由第三方快捷指令库自行组合，后端只提供同一项目的图片地址和动态视频地址。

## 1. 新建快捷指令和输入

命名为“高清作品保存”，在详细信息中打开“在共享表单中显示”，接收“文本”和“URL”。设置两个文本变量：

| 变量 | 内容 |
| --- | --- |
| API地址 | `https://media.example.com`，以实际部署地址为准 |
| Token | 服务器 Compose 环境变量中的 `API_TOKEN` |

快捷指令输入有值时读取“快捷指令输入”；否则读取剪贴板，将结果设为“分享文本”。

## 2. 提交和轮询

向 `API地址/v1/jobs` 发起 POST：请求头为 `Authorization: Bearer Token`，请求体 JSON 为 `{"text":"分享文本"}`。

读取返回词典的 `poll_url`，每 2 秒 GET 一次，直到 `status` 为 `succeeded` 或 `failed`。失败时显示 `error.message` 并停止。

`status = succeeded` 的分支必须放在“重复”内部：完成 `media` 保存后立即执行“停止此快捷指令”。不要把“停止此快捷指令”放在重复动作外，也不要在保存媒体时再次进入任务轮询。一个 Live 图集可能包含多个 `live_photo` 项，媒体遍历完成前继续循环是正常的。

## 3. 保存媒体

遍历 `media`，根据 `kind` 分支。

### `video`

读取 `url` →“获取 URL 内容”（GET）→“存储到相簿”。下载时保留完整 URL，包括 `expires` 和 `sig` 参数。

### `image`

读取 `url` →“获取 URL 内容”（GET）→“存储到相簿”。

### `live_photo`

后端返回同一动态图片项目的三个地址：

```json
{
  "kind": "live_photo",
  "url": "原始静态图片签名地址",
  "motion_url": "动态视频签名地址",
  "motion_photo_url": "安卓 Motion Photo JPEG 签名地址"
}
```

把 `url` 和 `motion_url` **原样**传给你选择的第三方 Live Photo 快捷指令库。第三方快捷指令负责下载、配对和保存到相簿；不要改写签名 URL、追加扩展名或把两个地址当作一个 ZIP。`motion_photo_url` 是安卓 Motion Photo 文件，按需单独保存。

如果第三方快捷指令只接受文件而不接受 URL，先分别对 `url`、`motion_url` 使用“获取 URL 内容”，再把得到的图片文件和视频文件传入它的图片/视频输入。不要把图片和视频分别交给“存储到相簿”后宣称已生成 Live Photo。

第三方快捷指令的动作名称、输入顺序和系统版本兼容性由其项目决定；本服务只保证这两个地址在任务保留期内有效，并保留对应的图片/视频请求头和签名。

每个媒体处理完后再处理下一项。全部分支完成后显示通知“已保存到相册”。

## 4. 反代和首次运行

API 会根据当前请求的 Host、协议、端口和路径前缀生成 `poll_url` 与媒体地址。快捷指令只需填写实际入口，例如 `https://media.example.com`。

首次运行时允许快捷指令访问服务器并写入照片。使用移动网络时必须使用公网 HTTPS 域名或 VPN，不能直接访问局域网地址。

## 结果检查

后端只负责解析、下载和提供签名地址；图片与动态视频的配对保存由第三方快捷指令完成。服务不会生成或返回资源包。
